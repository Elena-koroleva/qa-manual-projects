# ⚙️ Тестирование API бэкенда веб-сервиса «Яндекс.Прилавок» при помощи Postman

Проект демонстрирует навыки тестирования REST API и интеграционного тестирования бэкенда, составления чек-листов на основе технической документации (Apidoc), работы с форматами JSON/XML, локализации серверных дефектов и оценки рисков информационной безопасности.

---

### 🛠 Стек и инструменты
* **Тестирование и отправка запросов:** Postman (REST API, методы GET, POST, PUT, DELETE)
* **Форматы данных:** JSON, XML
* **Тест-дизайн и отчетность:** Google Таблицы (чек-лист API, баг-репорты)

---

### 📝 Описание проекта
Разработчики передали на тестирование новую функциональность API Яндекс.Прилавка. Задача заключалась в анализе требований в Apidoc, проектировании чек-листа для комплексного покрытия новых эндпоинтов (без учета авторизации) и проведении ручного тестирования бэкенда на тестовом стенде.

**Тестируемые эндпоинты (ручки):**
* **Работа с наборами:** `POST /api/v1/kits/{id}/products` — добавление продуктов в набор (JSON).
* **Работа с курьерами:** `POST /fast-delivery/v3.1.1/calculate-delivery.xml` — расчет стоимости и доступности доставки курьерской службой «Привезём быстро» (XML).
* **Работа с корзиной:**
  * `GET /api/v1/orders/id` — получение списка продуктов в корзине.
  * `PUT /api/v1/orders/:id` — добавление продуктов в корзину.
  * `DELETE /api/v1/orders/:id` — удаление корзины.

### 📋 Отчет о тестировании и рекомендации (Test Summary Report)

#### 🚨 Итоговое заключение:
На текущий момент приложение **не готово к релизу**. Выявленные проблемы могут привести к потере заказов, ошибкам в расчётах доставки и некорректной работе сервиса для конечных пользователей.

#### 🔍 Критические уязвимости и обоснование причин:
1. **Блокирующий дефект (Blocker):** Обнаружен баг, который полностью препятствует созданию корзины в определённое время (дефект исчезает только после 11:00 по МСК).
2. **Падения сервера (ошибки 500):** Найдено большое количество Critical-ошибок, приводящих к `500 Internal Server Error`. Это создает потенциальную уязвимость безопасности, которой могут воспользоваться злоумышленники.
3. **Нарушение бизнес-логики:** Система принимает некорректные входные данные. Наблюдается некорректная работа ключевых функций: расчёта стоимости доставки, добавления товаров в корзину и удаления корзины.
4. **Документация:** Обращено внимание на неточности в технической документации Apidoc — расчет доставки с 0 шт. и 0 кг (по бизнес-логике расчет должен происходить начиная с 1 шт. и 0.1 кг).

#### 💡 План необходимых работ перед релизом:
* Полностью устранить блокирующий баг и дефекты с приоритетом Critical.
* Реализовать строгую валидацию входных данных на стороне бэкенда.
* Настроить корректную обработку ошибок API (исключить появление необработанных ошибок 500).
* Провести комплексное повторное и регрессионное тестирование после исправления дефектов.
